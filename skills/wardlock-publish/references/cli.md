# Wardlock CLI: what this skill uses

Only the commands and `--json` output the skill needs. The full reference is the [CLI section of SPEC](https://github.com/CubieCode/wardlock/blob/main/docs/SPEC.md#cli-c15-c17-c19) and its [`--json` output](https://github.com/CubieCode/wardlock/blob/main/docs/SPEC.md#--json-output-c15); share links are in [Share links](https://github.com/CubieCode/wardlock/blob/main/docs/SPEC.md#share-links-a22) and path deploys in [Path deploys](https://github.com/CubieCode/wardlock/blob/main/docs/SPEC.md#path-deploys-c113).

`--json` prints exactly one JSON object on stdout and never prompts; on failure stdout is empty and stderr has `wardlock: <message>`. Exit status: 0 success, 1 failure, 2 usage error. Write `--json` where this table does: `policy set` refuses it before `policy` (a usage error), while the other commands take it before or after. The server comes from `--server`, then `wardlock.json`, then `WARDLOCK_SERVER`, then the last login.

| Command                                                                  | `--json` output                                                                                                                                                                                        |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `wardlock --json version`                                                | `{version, server?: {url, version}}`; `server` only when `WARDLOCK_SERVER` (or `--server`) is set.                                                                                                     |
| `wardlock --json list`                                                   | `{sites: [Site + policy]}`; `policy` is `public` or `protected` (the site's default policy). Fails with "not logged in" without a login.                                                               |
| `wardlock --json list ROOT`                                              | `{site: Site, deploys: [Deploy]}`, newest first. A path deploy's `Deploy` has `path` (`/slug/`); a whole-site deploy has none.                                                                         |
| `wardlock --json deploy DIR ROOT --message M`                            | An `Activation` (`site`, `deploy`) plus `siteCreated`, `uploaded` (`{files, bytes}`) and `skipped`. Creates ROOT if it does not exist.                                                                 |
| `wardlock --json deploy DIR ROOT --path /slug/ --message M`              | As above, plus `path`. Replaces only `/slug/`; the rest of the site stays live.                                                                                                                        |
| `wardlock --json deploy EMPTY_DIR ROOT --path /slug/ --yes --message M`  | As above. An empty DIR removes `/slug/`; `--yes` is required with `--json`. Never creates the site.                                                                                                    |
| `wardlock policy set ROOT --protected --links --json`                    | The API's `Policy` as set: `path` (`/`), `visibility` (`protected`), `methods` (`[links]`). Also `--password` (read from stdin), `--email`, `--oauth`, `--allow LIST`, `--github-org LIST`.            |
| `wardlock --json share create ROOT --path /slug/ --label L --expires 7d` | `{shareLink, token, url}`. The only time `url` and `token` are shown. `--expires` is `never` (the default) or `30m`, `1h`, `7d`, `2w`, and so on.                                                      |
| `wardlock --json share list ROOT`                                        | `{site: Site, links: [ShareLink]}`: `publicId`, `label`, `path`, `status`, `uses`, `expiresAt`, `lastAccessedAt`. Never a URL or token.                                                                |
| `wardlock --json share revoke ROOT LINK_ID`                              | `{revoked: true, site: Site, publicId}`. A missing or already revoked link is a failure.                                                                                                               |
| `wardlock --json share rotate ROOT LINK_ID`                              | `{shareLink, token, url}` with a new URL; the old one stops working.                                                                                                                                   |
| `wardlock --json teardown ROOT --yes`                                    | `{deleted: true, site: Site}`. Only to undo a root site that this same run created (its placeholder deploy reported `siteCreated: true`) and could not protect; never for a site that already existed. |

`Site` has `name`, `hostname`, `url`, `activeDeployId` and `unavailable`. `Deploy` has `id`, `status`, `createdAt`, `fileCount`, `totalSize` and, when set, `message` and `path`.
